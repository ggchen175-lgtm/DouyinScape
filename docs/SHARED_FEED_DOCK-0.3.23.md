# 0.3.23 共享视频详情底栏适配

## 问题与变更
稍后再看播放页与评论/私信视频使用相同的 RTViewPager + BottomSpace 关系，但底栏为播放列表按钮，没有 EditText，旧 PublicVideoSafeArea 因此漏识别。

现将编辑器分支与可交互底栏分支统一交给 bindAnchor / isSharedViewport。要求可见、屏幕下半部、短而全宽的操作栏，并确认它与同时含原生 RTViewPager、BottomSpace 的视频分支同属一个父级；不依赖页面标题、Activity 白名单或资源 ID。测量安全区差值后只由公共父容器补 padding，进度条、合集、底栏共同重新测量。已有原生避让的页面按差值补齐，键盘显示时归零，解除绑定恢复模块写入。

## 本次及近期规则复用检查
| 结构 | 位置写入职责 | 复用边界 |
| --- | --- | --- |
| 评论/私信视频详情，及稍后再看等无输入框详情底栏 | PublicVideoSafeArea | 共用原生视频+BottomSpace+独立底栏关系；VideoBottomOverlays 命中公共规则后直接返回，避免重复位移 |
| 双指放大播放 | PinchVideoSafeArea + HomeTabSafeArea | 同一 VideoPinchView 结构共用视口延伸；首页占位仍由原控制器释放/恢复，不套普通详情底栏规则 |
| 聊天输入及文字触发表情推荐 | ChatDockGeometry | 推荐栏为独立 GifSearchPanelLayout 时补实际重叠；已在输入框内部时不重复移动；主题不写位置 |
| 图文、音乐/玩法、听抖音等不同布局 | 原有结构控制器 | 本次没有强行并入视频父容器规则；布局职责不同，不以“在底部”作为唯一识别条件 |

## 实机验证
OnePlus 15 / Android 17 / 抖音 40.8.0：稍后再看底栏由 y2600 移至2544，底边2716，安全区2716–2772；进度条 y2572→2516；公共父容器 paddingBottom=56，背景仍铺满2772。列表展开背景连续，关闭后 padding 仍56，没有累计。构建通过。

其他入口的相同结构已由代码统一覆盖；本轮未逐一重新打开所有入口，也未验证所有机型和抖音版本。

## 后续首次绘制约束（0.3.24）
布局变化立即使公共底栏结构发现失效，不受后台搜索节流限制。设置父容器 padding 后，在原生子控件完成重新测量前，pre-draw 必须返回 false；不能仅以 padding 值已相等判断可显示。保留原生页面入场动画，不额外播放“补抬高”动画。该约束用于所有复用公共视频详情控制器的入口。0.3.24 已编译安装，稍后再看入场录像验证完成，详见 ENTRY_DRAW-0.3.24.md。
