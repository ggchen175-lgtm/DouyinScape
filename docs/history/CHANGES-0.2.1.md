# 0.2.1 原包布局与生命周期修正

基于0.2.0，versionCode=2，包名保持 cn.zhe.douyinunified，可覆盖安装。旧独立两个模块继续停用。

## 参考资料

已解码并查看用户提供的三段 iOS 参考录屏：导航栏及任务栏沉浸样式、暗色浅色模式热切换、底部按钮切换。采用其背景连续、随页面移动、控件及时变色且完整可见的效果方向，保留 Android 原生尺寸、控件与系统手势行为。

原包40.7.0交叉分析：

- RipsChatRoomFragment 的 onViewCreated/onDestroyView，用于确认聊天页面身份，涵盖没有输入框的群聊。
- CustomRecyclerView 实际定义在 classes40.dex，继承 ChatRecyclerView；聊天列表资源 id=v6m(0x7f0a919e)。
- InputDisableBarUI 使用 r/0du.xml：64dp LinearLayout，内部 mzi(0x7f0a57a4) 为禁言提示，背景0x7f060040为主题半透明色。
- NewMsgTipsUI 的 te0/te1/tez 结构及 onNewMsgTipStataChange 回调，用于同步原生圆按钮背景及箭头背景。

## 四项修正

1. 自定义壁纸侧滑返回：导航栏小范围补绘原生壁纸与同一背板颜色，按实际 dock 可见横向边界裁定补绘区域。解决仅叠加半透明色到消息页底色上，导致壁纸区域底部成为灰带的缺口。无需重新布局或缩放壁纸，绘制只限制于导航 inset。

2. 进入聊天气泡二次上抬：新增 ChatListInsets，在原生 setPadding/onMeasure 阶段补足聊天列表预留空间，避免首次已显示后再补 padding。沉浸引擎与该对象共享原始/已施加值，保持幂等。

3. 返回消息列表白带：移除从整个 Activity 中任意选择 RecyclerView 的兜底，只处理聊天 Fragment 子树内确定的 CustomRecyclerView，排除建议列表。聊天 onDestroyView 时还原其留白和补绘，随后对可见视图做一次重绘，不再等待用户滚动才刷新。

4. 禁言群聊：以聊天 Fragment 判定当前页面，不再依赖普通输入框存在。热切后和原生新消息提示状态变化后同步按钮原生资源；将圆按钮容器限位到禁言栏与祖先裁剪边界上方，保留父容器原生裁剪，不把消息区整体解除裁剪。禁言栏背景单独延伸到导航区；不对该页套普通输入框的额外56px留白和位移，避免反复纠偏。

## 保留项与限制

普通聊天 CHAT_LIFT_PX=56、键盘额外消息间隔68、首页标签、直播37px及私信视频T5逻辑保持原值；高刷策略和三个开关沿用0.2.0。本轮未调整此前搁置的进入聊天转场动画。

离线编译和APK签名检查通过。未连接ADB、未做设备功能或性能验收。以上是源码修正与原包分析结论，不能代替用户真机验收，也不宣称已完全复制 iOS 渲染。

建议优先复测四条原路径：壁纸侧滑返回、点击会话观察气泡、返回消息页静置观察底部白带、禁言群聊深浅热切观察按钮和导航栏。继续保留原始录屏，时序按原始PTS判断。
