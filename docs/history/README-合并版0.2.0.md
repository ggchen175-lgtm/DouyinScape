# 抖音沉浸与主题 0.2.0

## 安装

这是新的合并模块，包名 `cn.zhe.douyinunified`，可与旧包共存，但不能同时对抖音生效。

1. 安装合并版 APK，打开桌面「抖音沉浸与主题」一次。三个开关默认打开。
2. 在 LSPosed 停用旧的「小白条沉浸」及「跟随系统主题」模块，或取消它们的抖音作用域。
3. 启用合并模块，作用域勾选抖音。
4. 彻底关闭并重新启动抖音；若新模块未被加载，再重启手机。

抖音内部主题选项继续保持「跟随系统」。开关修改后需重新启动抖音。

## 本次集中处理

### 1. 壁纸聊天底栏颜色断层 / 滚动时导航栏变色

沉浸引擎统一发布实际 dock、上抬容器、消息列表和 IME/面板状态，主题引擎使用同一份绑定结果。回复/输入区的大块背板采用原生壁纸面板主题色，导航栏区域延续同一透明度；移除原先直接重复绘制壁纸的路径。保留圆角输入控件，不让补绘盖住文本和按钮。

### 2. 从聊天页侧滑返回时状态栏仍整条灰色

顶部背景按实际跟随侧滑的 dock 横向位置绘制，替代可能始终全屏的 Rips Fragment 根节点作为边界依据；绘制时再次读取位置。消息页底色与聊天页底色分别覆盖对应区域，不修改原生转场时长。

### 3. 进入聊天后消息突然向上抬

保持结构变化监听，动态插入时不再等常规100ms发现间隔；进入时立即寻找列表并补底部空间。首次 padding 请求布局后，至多等待3帧/100ms让布局完成；该实例稳定后不重复挡帧。去掉主题焦点恢复时不必要的整页 requestLayout。

## 性能处理

- 单一模块入口，先建立沉浸几何，再启动主题观察；不同时加载旧模块。
- 已找到的聊天 dock 使用共享弱引用缓存，减少逐帧整树搜索和反射。
- 结构修复、回复面板发现、圆按钮同步、消息预览扫描按结构/主题变化及时间间隔运行；轻量位置约束仍逐帧执行。
- 对合法的、比 View 窄的原生文本布局不再反复重建，保留语音预览修复。
- 不添加持续刷新/强制重绘循环，不缩放媒体 viewport。

## 高刷

独立「请求屏幕最高刷新率」开关。读取当前分辨率下的 supportedModes，并保留当前实际更高的显示刷新率，使用窗口 preferredRefreshRate 请求最高值；普通 Activity、Dialog 和应用子窗口走同一规则。显示模式变化时重新选取，不写死165，不改变分辨率、不修改视频源帧率。

这是刷新率请求，不是对实际应用 FPS 的保证。系统省电、温控、厂商策略、渲染负载及视频源帧率仍可影响实际表现；没有设备测量不能宣称所有界面达到165FPS。

机制参考：[Android WindowManager.LayoutParams](https://developer.android.com/reference/android/view/WindowManager.LayoutParams)、[Android Frame rate](https://developer.android.com/media/optimize/performance/frame-rate)。
