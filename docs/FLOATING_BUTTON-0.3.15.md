# 0.3.15 聊天快速下拉按钮

问题：0.3.14 的定位与主题识别仍依赖 40.7 的 te0/te1/tez 数值 ID。手机当前版本使用 te6/te7/te5，旧逻辑未命中，按钮阴影及圆形下缘被已上移的快捷表情栏覆盖。上一版整理没有覆盖该控件变体。

修正：
- ChatFloatingControl 根据聊天根内的原生 ShadowFrameLayout、LayerDrawable 圆形宿主与 ImageView 子控件识别，排除 RecyclerView 消息行。允许宿主含隐藏的计数文字，不假设只有一个子控件。
- ChatFloatingGeometry 计算完整阴影 wrapper 的边界，位于输入 dock 顶部 8dp 以上，并遵守祖先裁剪边界；未关闭整个聊天区域的裁剪。
- 显示为 200ms 渐显、0.86→1 缩放；隐藏为 160ms 缩小淡出。动画使用系统 ValueAnimator，遵守系统动画时长倍率。
- 原生 visibility、点击监听和父子关系保持不变。原生设为 GONE 后，使用仅包含按钮面的微小位图在聊天根 overlay 完成退出，覆盖层不拦截点击；切换会话/销毁时取消动画、移除覆盖并释放位图。
- 主题与导航共用结构识别。40.7 的两个 drawable 数值资源 ID 仅在旧 te0 变体使用，新布局保留其原生背景，避免替换成版本不对应的资源。

验证：看过用户 iOS 与本机录屏，并抽帧对比。手机当前同一群聊的实测 wrapper 为 y2128..2335，快捷栏/dock 顶边为2363，阴影有28px间距；圆形面 y2167..2296，保持完整。滑动录屏中按钮不裁切，另一次录屏捕获了渐显/缩放及缩小淡出；点击仍停留在聊天页并触发原生快速下拉。键盘打开输入 dock y1424..1630，关闭恢复 y2363..2716，导航背景仍透明。没有发送聊天消息。

限制：按所给 iOS 参考实现显隐过渡，没有声称逐像素、逐帧复刻 iOS；原生应用仍决定何时显示按钮及下拉目标。未重测所有远端布局变体。

源码包不含手机录屏、截图、消息内容或签名私钥。换电脑构建需修改本机签名路径。
